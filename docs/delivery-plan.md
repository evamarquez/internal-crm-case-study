# Delivery plan

## Phases

| Phase | Main action | Result |
|---|---|---|
| Discover | Map fields, views, ownership, dependencies, and hidden rules. | Shared picture of the real operating model. |
| Design | Separate clients, brands, projects, deliverables, and ownership into a target schema. | Model based on real entities and relationships. |
| Build | Create dashboard views, clean mappings, and prepare representative records. | Usable workflow for high-frequency work. |
| Validate | Run old and new workflows in parallel and test selected scenarios. | Gaps, decisions, and issues visible before cutover. |
| Roll out | Publish SOPs, support adoption, and hand over ownership notes. | System the team can continue operating. |

## Delivery controls

- Use representative scenarios, not only an empty or idealised database.
- Keep coexistence long enough to discover missing states and ownership questions.
- Record decisions and known issues as delivery outputs.
- Treat handoff as part of completion, not a post-project memory exercise.
